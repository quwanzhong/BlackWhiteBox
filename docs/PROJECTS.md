# 项目级测试：代码 × Apifox 接口 × 业务闭环

> 同一份 Apifox 文档往往服务多个前端工程。黑百盒用「项目」把 **本机代码目录**、**该项目实际用到的接口**、**源码调用流程** 和 **可执行测试流程** 绑在一起，避免每个项目重复挑接口、手工拼流程。

## 1. 核心概念

| 概念 | 说明 |
|---|---|
| 项目 | 一个前端工程。记录本机绝对路径 `codePath`、被测服务地址、Apifox 连接标识 |
| 接口绑定 | 从同一份 Apifox 文档里勾选本项目用到的接口，保存 **完整元数据快照** |
| 调用点 | 源码里的一次 HTTP 调用（`axios.get('/users')`、`request({ url, method })`、`fetch()`） |
| 匹配 | 调用点路径 ↔ 已绑定接口路径，从末尾逐段比较，支持 `{}` 占位符 |
| 业务功能 | 一组相关的调用点/接口。按 Apifox 目录 → 接口路径首段 → 代码目录依次兜底 |
| 闭环流程 | 按源码调用顺序生成的黑色流程，节点可直接执行并逐项校验 |

项目数据保存在 `backend/data/projects.json`，缺陷保存在 `backend/data/bugs.json`，均为本机文件。

## 2. 代码目录怎么关联

黑百盒 **不上传、不复制代码**，只保存一个本机绝对路径，扫描时由后端直接读取该目录。

1. 进入 **项目管理 → 新建项目**；
2. 点「代码目录」右侧的 **选择目录**；
3. 在目录选择器里逐级进入，或直接把 `C:\work\my-app` 粘贴到地址栏回车；
4. 检测到 `package.json` / `src` / `vite.config.*` 时会显示绿色「工程」标记；
5. 选中后点「使用该目录」。

> 目录浏览器只列出文件夹，不读取文件内容。项目详情页和项目设置里都可以重新选择目录。

## 3. 完整操作流程

### 3.1 新建项目

填写项目名、描述、代码目录、被测服务地址（可空）。Apifox 连接是**全局单例**：在「数据导入」页配置一次项目 ID + 令牌，所有项目共用，项目本身不再重复填写。

### 3.2 勾选项目接口

进入项目详情 →「① 绑定 Apifox 接口」：

1. 首次使用先在「数据导入」页完成**全局 Apifox 连接**（项目 ID + 访问令牌），只需配置一次，黑盒导入与所有项目共用；
2. 进入项目详情点「拉取 / 刷新接口」；返回的接口列表带 Apifox 目录、方法与路径；
3. 按目录筛选 / 关键词搜索，勾选本项目真正用到的接口；
4. 点「保存勾选」。此时会把每个接口的路径参数、必填 query、请求体示例、目录、服务地址一起写入项目快照。

> 绑定后不再依赖 Apifox 缓存：后续扫描、生成流程都读项目快照。
> 令牌只用于连接，不写入配置文件；连接参数与接口缓存全站单例。

### 3.3 扫描代码调用流程

进入「② 扫描代码调用流程」：

1. 确认代码目录与被测服务地址；
2. 点「开始扫描」；
3. 查看统计：扫描文件数、调用点数、已匹配 / 未匹配、匹配率、业务功能数；
4. 调用点表格按「文件 + 行号」排序，即源码中的真实调用顺序；
5. 置信度低或未匹配的调用点，点「关联」手动选择接口；清空选择即取消关联。

扫描规则：

- 识别 `.js / .ts / .jsx / .tsx / .vue / .mjs / .cjs`；
- 识别三类写法：
  - 成员调用：`axios.get('/users')`、`service.post('/orders', data)`；
  - 函数调用：`fetch('/users')`、`request('/users')`；
  - 对象参数：`request({ url: '/users', method: 'post' })`；
- 跳过 `node_modules / dist / build / .git / public / static / assets` 等目录；
- 默认最多 3000 个文件、单文件 2MB、最多保留 1200 个调用点（可通过扫描参数调整上限）；
- 只做静态文本/语法级分析，不执行代码；动态拼接、变量间接传参可能识别不到，需要手动关联。

路径匹配规则：

1. 去掉域名、`?query`、`#hash`，把 `${id}` / `{{id}}` / `{id}` 统一成 `{}`；
2. 从路径末尾逐段比较，`{}` 可匹配任意一段；
3. 已知方法时方法必须一致；
4. 末尾段必须匹配，得分 = 匹配段数 / 较长路径段数；
5. 兼容 `/api` 前缀差异，例如代码 `/api/users` 能匹配文档 `/users`。

### 3.4 业务功能划分

扫描完成后自动进入「③ 业务功能闭环」。分组优先级：

1. **Apifox 目录**（`x-apifox-folder`）——推荐在 Apifox 里维护好目录；
2. **接口路径首段**——没有目录时按 `/order/...`、`/user/...` 归组；
3. **代码目录**——未匹配到接口的调用点按所在源码目录归组。

每组显示接口数、调用数、文件数。没有接口的组不能生成流程，但保留展示，方便发现漏绑或漏匹配。

### 3.5 生成并执行闭环流程

- 「生成全量流程」：把所有已匹配调用点按源码顺序生成一条流程；
- 「生成选中功能流程」：每个勾选的业务功能生成一条流程；
- 生成后在「已生成流程」里打开，节点顺序即源码调用顺序（文件、行号），不是 Apifox 文档顺序；
- 同一流程内同一个接口只保留一个节点，位置取源码中首次出现处（避免多个页面复用同一接口导致流程重复）。

节点自动生成规则：

- URL = 项目/接口服务地址 + 接口路径；没有服务地址时用 `{{baseUrl}}`；
- 路径参数转成 `{{参数名}}` 并写入流程变量（取 Apifox 示例值）；
- 必填 query 参数拼到 URL，同样写入变量；
- 非 GET/DELETE/HEAD 请求带 Apifox 请求体示例；
- 理想输出默认：GET/PUT/PATCH/DELETE 期望 200，POST 期望 201；校验项可在画布节点里继续补充。

执行时画布节点依次呼吸发光，报告里逐项展示实际输出与理想输出是否一致。失败步骤可直接「提缺陷」。

## 4. 缺陷反馈

- 报告详情页：失败 / 校验不一致的步骤右侧有「提缺陷」，自动带入流程、请求、错误、校验差异；
- 缺陷页：手工登记、按项目 / 状态 / 级别筛选、修改状态（待确认 → 已确认 → 修复中 → 待验证 → 已验证 / 已关闭 / 已驳回）；
- 缺陷记录关联 `projectId / flowId / executionId / nodeId / stepName`，并保存实际值与期望值快照。

|---|---|---|
| GET | `/api/projects` | 项目列表（含扫描摘要、流程数、未关缺陷数） |

| POST | `/api/projects/:id/mapping` | 手动关联 / 取消关联调用点 |

## 6. 安全与限制

- 目录浏览与代码扫描只服务 **本机单机版**，没有鉴权，不要把端口暴露到公网；
- 不读取、不上传代码内容，扫描结果只在本机 JSON 中保存调用点的文件、行号、函数名和路径；
- Apifox 令牌不落盘；
- 扫描是启发式的：动态 URL、封装层级很深的自定义请求库、模板字符串运行时拼接可能漏识别，允许手动关联兜底；
- 同一份 Apifox 文档被多个项目复用时，每个项目各自保存接口快照，互不影响。

## 7. 常见问题

**扫描结果为空？**
确认目录选的是前端源码根目录（含 `src`），不是仓库父目录；确认接口已保存勾选；查看是否有 `node_modules` 之外的特殊构建目录被跳过。

**匹配率低？**
Apifox 文档路径与代码请求前缀差异过大时，匹配分数会下降。可在扫描结果里手动关联；建议在 Apifox 中统一路径前缀。

**改了代码要重新生成流程吗？**
重新扫描会更新调用点与分组；已生成的旧流程不会自动改写，按需重新生成。生成新流程不会删除旧流程。

**为什么生成流程的 URL 是 `demo.example.com`？**
项目被测服务地址为空时取接口文档里的 `servers[0].url`；联调前把项目「被测服务地址」改成真实环境即可重新生成。
